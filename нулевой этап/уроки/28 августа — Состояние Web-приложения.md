# 28 августа — состояние Web-приложения

**Цель:** понять состояние, идентичность и разрешения. **Результат:** схема login → session/token → authorization check.

## Теория

Authentication отвечает «кто ты?», authorization — «что тебе разрешено?». Cookie — механизм хранения/передачи данных браузером; session обычно хранит состояние на сервере и связывает его с идентификатором. Token — формат/значение полномочий, но его безопасность зависит от реализации. Разбери forms, JSON API, URL parameters и Same-Origin Policy на базовом уровне.

## Безопасная практика

В DevTools → Network изучи разрешённое приложение или учебную лабораторию: метод, URL, status, headers, cookies и JSON. Значения session/token замажь и не копируй в базу. Опционально пропусти свой учебный запрос через Burp Suite Community.

## Самопроверка

1. Почему успешная аутентификация не даёт доступ ко всему?
2. Где может храниться серверная сессия?
3. Каковы роли `Secure`, `HttpOnly`, `SameSite`?
